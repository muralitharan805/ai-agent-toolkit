# Clean Code & Maintainability Standards

## Description
Enforces strict Clean Code guidelines across all code generated by AI agents and developers. Ensures that code is self-documenting, readable for fresher/junior developers, strictly typed without `any`, and scalable over long-term project lifecycles.

## Constraints

### 1. Mandatory TSDoc / JSDoc Block Comments
- Every exported class, interface, service method, controller endpoint, and utility function MUST include TSDoc block comments (`/** ... */`).
- Block comments MUST document business purpose, `@param` descriptions, `@returns` payload description, and `@throws` exceptions.
- Undocumented public API methods are STRICTLY FORBIDDEN.

### 2. Magic Value Prohibition Rule
- Magic numbers, inline string literals, and un-enumed status flags MUST NOT be used in conditional logic.
- All status flags, roles, and constant values MUST be defined using TypeScript `enum` or `readonly` constant objects.

### 3. Function Length & Parameter Limits
- Functions MUST NOT exceed 35 lines of code without refactoring into helper methods.
- Functions MUST NOT accept more than 3 positional parameters; functions requiring 4 or more inputs MUST use a typed DTO class or options object.

### 4. Guard Clauses / Early Return Requirement
- Code MUST NOT contain nested `if/else` conditions deeper than 2 levels.
- Precondition validation MUST use guard clauses (early `return` or early `throw`) to flatten execution flow.

### 5. Intention-Revealing Naming
- Variable and function names MUST be descriptive and self-explanatory (e.g. `calculateLoanAmortizationSchedule` instead of `calc`).
- Single-letter variable names (e.g. `x`, `temp`, `data2`) are forbidden except in simple loop counter indexes (`i`, `j`).

### 6. No `any` Type Enforcement
- Writing `any` as an explicit type annotation for variables, parameters, return types, or type assertions is STRICTLY FORBIDDEN.
- Use specific interfaces, generics, `unknown` with type narrowing, or utility types (`Record<string, unknown>`) instead of `any`.
- If an external library lacks types, declare a minimal custom interface or type boundary.

## Examples

### 1. Mandatory TSDoc Block Comments vs. Undocumented Export
```typescript
// ❌ FORBIDDEN: Undocumented public API method
export function calculateEmi(p: number, r: number, n: number): number {
  const m = r / 12 / 100;
  return (p * m * Math.pow(1 + m, n)) / (Math.pow(1 + m, n) - 1);
}

// ✅ CORRECT: Fully documented with business purpose and parameter details
/**
 * Calculates monthly EMI installment amount for an amortized loan.
 *
 * @param principalAmount - Total loan amount in base currency units
 * @param annualInterestRate - Annual interest rate percentage (e.g. 8.5 for 8.5%)
 * @param tenureInMonths - Total repayment term in months (e.g. 240)
 * @returns The calculated monthly installment payable
 * @throws {BadRequestException} When principal, rate, or tenure are non-positive
 */
export function calculateMonthlyEmi(
  principalAmount: number,
  annualInterestRate: number,
  tenureInMonths: number
): number {
  if (principalAmount <= 0 || annualInterestRate <= 0 || tenureInMonths <= 0) {
    throw new BadRequestException('All EMI parameters must be strictly positive');
  }
  const monthlyRate = annualInterestRate / 12 / 100;
  const factor = Math.pow(1 + monthlyRate, tenureInMonths);
  return (principalAmount * monthlyRate * factor) / (factor - 1);
}
```

### 2. Parameter DTO vs. Long Positional Parameter List
```typescript
// ❌ FORBIDDEN: 5 positional parameters (error-prone argument order)
function registerUser(name: string, email: string, age: number, role: string, notify: boolean): User { ... }

// ✅ CORRECT: Encapsulated into typed DTO interface
export interface RegisterUserDto {
  readonly fullName: string;
  readonly emailAddress: string;
  readonly age: number;
  readonly role: UserRole;
  readonly enableNotifications: boolean;
}

export function registerUser(dto: RegisterUserDto): User { ... }
```

### 3. Guard Clauses vs. Deeply Nested Conditionals
```typescript
// ❌ FORBIDDEN: Deeply nested conditional pyramid (> 2 levels)
function processOrder(order: Order): void {
  if (order) {
    if (order.items.length > 0) {
      if (order.isPaid) {
        dispatch(order);
      }
    }
  }
}

// ✅ CORRECT: Flattened flow with early return / throw guard clauses
function processOrder(order: Order): void {
  if (!order) {
    throw new BadRequestException('Order payload is required');
  }
  if (order.items.length === 0) {
    throw new BadRequestException('Order must contain at least one item');
  }
  if (!order.isPaid) {
    throw new PaymentRequiredException('Order is not yet paid');
  }
  dispatch(order);
}
```

### 4. Strict Type Narrowing (`unknown`) vs. Forbidden `any`
```typescript
// ❌ FORBIDDEN: Using explicit any disables type checking
function parseUserData(input: any): any {
  return input;
}

// ✅ CORRECT: Strict unknown with user-defined type guard
export function parseUserData(input: unknown): UserProfile {
  if (isUserData(input)) {
    return input;
  }
  throw new BadRequestException('Invalid user payload format');
}
```
