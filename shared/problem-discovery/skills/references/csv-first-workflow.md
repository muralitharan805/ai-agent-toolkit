# CSV-first Problem Discovery — one file, one row per candidate

## Source of truth

Use **one `discovery_matrix.csv`** for the entire discovery project. `scripts/discovery_csv.py` accepts one JSON candidate or an array and updates the matching `candidate_id` row; unrelated candidates and manual `research_notes` remain intact. A subsequent call with a new ID inserts a new row. It writes atomically and reorders by the 35-point *research priority* score; rank does not mean actual market validation. The scorer is run again for every updated candidate rather than trusting hand-edited status cells.

```bash
python3 scripts/discovery_csv.py --input-json input_candidates.json --output ./discovery_matrix.csv
```

**No Markdown files are generated by this command.** The input JSON is caller-supplied; a CLI invocation may accept a temporary JSON payload, but the tool emits only the single persistent CSV. Store raw interview/audio/customer data outside the CSV, preferably in a private redacted evidence store; link a safe local artifact path, hash and human review metadata in the CSV.

## Main spreadsheet columns

`candidate_id`, `problem_title`, `domain`, `track`, `rank`, `total_score`, `classification`, `status`, `evidence_level`, `evidence_verified`, `experiment_completed`, `experiment_passed`, seven separate scoring dimensions, `recommended_action`, `research_notes`, `updated_at`.

Detailed fields use **JSON text within the same CSV row**, not extra files: `evidence_sources`, `evidence_artifacts`, `evidence_records`, `workflow_14_nodes`, `stop_checks_triggered`, `experiment`, `solution_constraints`, `smallest_solution`. Filter/sort on the ordinary columns; expand JSON text cells when reviewing a candidate. The CSV is safe for normal spreadsheet tooling, but avoid publishing sensitive information. Source pointers are not proof of authenticity.

## Minimum example input

```json
{
  "id": "PROB-RECON-001",
  "title": "Manual stock reconciliation at shift handoff",
  "domain": "Textiles",
  "track": "commercial",
  "evidence_level": 5,
  "scores": {
    "frequency": 0, "severity": 0, "workaround": 0, "wtp": 0,
    "decision_maker": 0, "feasibility": 0, "discrepancy": 0
  },
  "research_notes": "Hypothesis only; collect consented field observations before scoring."
}
```

Hypothetical examples must never be exported with fabricated evidence or marked validated. In practice, fill `workflow_14_nodes`, `evidence_records`, `experiment`, and `solution_constraints` as independently checked research becomes available; consult `evidence-audit-contract.md` for the exact contract.

## Compatibility with existing Markdown dossiers

`score_problem_candidate.py --export-obsidian DIR` and `export_discovery_matrix.py` remain available **only for explicitly requested legacy workflows**. Their CSV is regenerated from Markdown notes and has a different header: it is **not** interchangeable with the CSV-first register. To move an existing vault, back up your CSV, inspect the old notes and their original source artifacts, then construct candidate JSON for the CSV-first scorer. Never copy legacy `VALIDATED` / score-only labels into the new CSV without re-evaluating supporting primary evidence and the actual preregistered experiment. If a CSV already exists with an incompatible header, `discovery_csv.py` refuses to overwrite it. Use a new path until migration is reviewed.
