# AI Agent Toolkit Authoring, Architecture & Quality Standards

## Description
This rule governs all development, scaffolding, refactoring, and synchronization within the `ai-agent-toolkit` repository (`muralitharan805/ai-agent-toolkit`). It mandates that any AI agent operating in this codebase adhere to the official `agentskills.io` 5-pillar specification, the Principal Architect engineering mindset, modern framework currency, strict Antigravity rule triggers, automated Python validation gates, and zero-hardcoding synchronization standards.

## Constraints

### 1. Mandatory Deduplication & Smart Upsert
- Before creating a new file, the agent MUST inspect the workspace (`frameworks/`, `infra/`, `shared/`, `domains/`) for existing skills or rules covering the target topic.
- If a related component exists, the agent MUST update and merge new requirements into the existing bundle rather than creating duplicate or overlapping files.

### 2. The 5-Pillar Modular Skill Architecture (`agentskills.io` Standard)
Every skill scaffolded or modified in this repository MUST strictly implement the 5-pillar modular directory bundle:
- **Pillar 1: Core Instruction (`SKILL.md`)**:
  - YAML frontmatter: `name` (kebab-case matching directory name) and `description` (1–1024 characters in third-person imperative phrasing).
  - Body: Strictly under 500 lines. Structured around explicit execution phases, clear personas, and a mandatory `## Gotchas` section.
- **Pillar 2: Authoritative References (`references/`)**:
  - Granular API specifications, edge-case runbooks, and deep architectural guidelines loaded on demand.
- **Pillar 3: Agentic Execution Scripts (`scripts/`)**:
  - Standalone, idempotent CLI automation tools. Python scripts MUST use inline PEP 723 metadata (`# /// script ... ///`), emit structured JSON to `stdout`, diagnostics to `stderr`, and support `--help`.
- **Pillar 4: Assets & Starter Templates (`assets/`)**:
  - JSON schemas (Draft 2020-12), boilerplate configurations, and output templates.
- **Pillar 5: Empirical Verification Suites (`evals/`)**:
  - `evals/evals.json` containing realistic test cases with objective, binary assertions.
  - `evals/grading.json` generated by `run_evals.py` recording pass rates and net skill lift ($\Delta_{\text{skill}}$).

### 3. Principal Architect Mindset & Strict Currency Invariant
- **No Tutorial-Ware**: The agent MUST reject simplistic, "Hello World" happy-path examples. Code MUST handle concurrency, boundary validation, timeouts, and memory leak cleanup (e.g. `takeUntilDestroyed()`, stream unsubscriptions, component unmounting).
- **Latest Stable Frameworks ONLY**:
  - **Angular (v19+)**: Standalone components ONLY, fine-grained Signals reactivity (`signal`, `computed`, `resource`, `rxResource`), native block control flow (`@if`, `@for`), Typed Forms, and functional DI (`inject()`).
  - **NestJS**: Clean Architecture, Zod/class-validator DTOs, functional guards, and correlation ID tracing.
  - **Infra**: Compose v2, multi-stage BuildKit builds, non-root runtime users, and pnpm package management.
- **Zero Deprecated Patterns**: The inclusion of obsolete patterns (e.g. Angular `NgModule`, `@Input()`/`@Output()` decorators, `BehaviorSubject` for local state, untyped forms, or legacy Docker links) is STRICTLY FORBIDDEN.
- **Type Safety**: The use of explicit `any` types is strictly prohibited across all code and tests.

### 4. Antigravity Rules Specification & Trigger Optimization
- **Character Budget**: Rule files MUST target 6,000–8,000 characters (optimal for token economy). The absolute hard ceiling is 12,000 characters (IDE truncation limit).
- **Trigger Strategy Selection**:
  - `trigger: model_decision` (Recommended Default for domain and feature rules; saves context tokens by loading on-demand via natural language `description:`).
  - `trigger: glob` with `globs: [...]` (For language/filetype specific rules like styling or test suites).
  - `trigger: always_on` (Reserved exclusively for universal workspace invariants like clean code and authoring standards).
  - `trigger: manual` (For high-friction runbooks invoked explicitly with `@rule-name.md`).

### 5. Workflows Sunset & Procedural Skills Mandate
- Google Antigravity IDE has officially deprecated standalone workflows (`.agents/workflows/*.md`), with full retirement on November 1, 2026.
- The creation of new standalone `.agents/workflows/*.md` files is STRICTLY FORBIDDEN.
- All sequential processes, deployment pipelines, scaffolding tasks, and automation sequences MUST be authored as **Procedural Skills** under `skills/[skill-name]/` with bundled scripts and checklists.

### 6. Automated CLI Validation Gates
Before presenting any generated or edited skill or rule to the user, the agent MUST run the bundled automated validators:
- Validate Skill: `python3 shared/generators/skills/generate-skill/scripts/validate_skill.py <skill-path>`
- Validate Rule: `python3 shared/generators/skills/generate-rule/scripts/validate_rule.py <rule-path>`
- Verify Suite: `python3 shared/generators/skills/generate-agent-suite/scripts/verify_suite.py <target-dir>`
- Grade Evals: `python3 shared/generators/skills/eval-skill/scripts/run_evals.py <skill-path> --save-grading`

All scripts MUST exit cleanly with code `0` (zero errors, zero warnings).

### 7. Zero-Hardcoding Synchronization Protocol
- All synchronization into consumer workspaces (`.agents/`) or user global environment (`~/.gemini/`) MUST use `bin/sync-context.sh`.
- The agent MUST NEVER hardcode destination paths or rely on symlinks.

    ├── evals.json
